Типичные ошибки и быстрые решения

Найти причину по логам, восстановить узел и повторить нужную проверку

СимптомПричина и действие
docker: command not found или недоступен ServerРаботайте в Ubuntu WSL с установленным Docker Engine/Compose; сначала проверьте docker version.
Run bash scripts/lab6.sh init firstПодготовьте отдельные секреты командой bash scripts/lab6.sh init, затем up.
ENOTFOUND mongo2 у хостового клиентаОсновной сценарий работает через runner и Compose DNS. Для прямого WSL-клиента нужны все три имени в /etc/hosts, совпадающие с rs.conf().
Authentication failedИспользуйте прежние credentials соответствующего volume. Не генерируйте новый пароль наугад и не удаляйте тома.
Отсутствует pg_events.jsonВ настроенной Lab5 выполните bash scripts/lab5.sh sync. В основной сценарий Lab6 PostgreSQL-записи не входят.
check сообщает о старом seed или нет медианВыполните seed, benchmark, bulk, transaction, index-write либо весь all. После смены seed измерения нужно повторить.
status ждёт остановленный узелОн требует все три здоровых состояния. Для аварийной диагностики откройте shell выжившего узла и выполните replSetGetStatus.
NotWritablePrimary в ручной демонстрацииСнова найдите PRIMARY через status и откройте shell этого сервиса; имя mongo1 не закреплено за лидером.
Another Lab6 command is runningЗавершите текущий сценарий. flock сериализует изменения индексов, fixtures и failpoints.
check --with-failover не находит отчётСначала отдельно выполните failover --yes. Обычный all намеренно не останавливает PRIMARY.
Временные tx/bulk-документы после теста не найденыЭто ожидаемый cleanup. Смотрите assertions и JSON-отчёты; counts временных ID должны быть нулевыми.
Информация в HTML отличается от свежего CSVОткройте текущий artifacts-файл; HTML содержит снимок момента сборки. После новых измерений пересоберите инструкцию.
