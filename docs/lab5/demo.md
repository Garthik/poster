# Сценарий защиты: ЛР №5

Показывать из WSL в корне проекта. **Эти команды выполняются на ранее подготовленном PostgreSQL primary**; standby принимает только чтение. Не удаляйте `ha_primary` и `ha_replica`.

1. `./scripts/lab5.sh init && ./scripts/lab5.sh up` — MongoDB доступна локально на 27018 с отдельным паролем.
2. `./scripts/migrate.sh` (в окружении из `README.md`, подключаясь к актуальному primary через 5436) — миграция `003_lab5_comparison` создаёт изолированную JSONB таблицу для исследования.
3. При необходимости получить 75 тыс. сканов `SEED=20261004 ./scripts/generate_data.sh development` под `ticket_app`; если данные уже есть — пропустить.
4. `./scripts/lab5.sh sql` — показать `artifacts/lab5/sql_catalog_results.txt`, `sql_assertions.txt`, `PASS` по Q2/Q4/Q6/Q7/Q8.
5. `./scripts/lab5.sh schema` — создаёт три коллекции с `$jsonSchema` и индексами.
6. `./scripts/lab5.sh sync` — берёт реальные `app.events` и выпускает **редакционные** Mongo-документы, но не копирует заказы/билеты.
7. `./scripts/lab5.sh crud` — создаёт, читает, изменяет и удаляет документы во всех 3 коллекциях.
8. `./scripts/lab5.sh validation` — ожидаемые отказы `code 121` для неправильных типов/правил и проверка межколлекционных ссылок.
9. `./scripts/lab5.sh compare` — показ `artifacts/lab5/mongo_cards.json` и `postgres_cards.json`, результат `PASS`.
10. `./scripts/lab5.sh evolve` — `schemaVersion=1 → 2`, поле `readingMinutes`, повторный запуск должен показать `0` модификаций. `./scripts/lab5.sh compare` повторно подтвердит одинаковые результаты.

## Что отвечать по архитектуре

- PostgreSQL — источник истины для транзакций, FK, квот, мест и финансов.
- MongoDB — источник истины только для **редакторского контента**: содержательные секции страницы, тематические подборки и отзывы к статье.
- `event_pages.sections` **embedded**, поскольку читаются вместе с заголовком и ограничены до 15 элементов; подборки хранят **references** `pageSlugs`, потому что страницы переиспользуются и редактируются независимо.
- `editorial_collections.pageSlugs` — M:N, `visitor_feedback.pageSlug` — 1:N.
- В отличие от PostgreSQL, в MongoDB нет автоматически поддерживаемых FK: проверить ссылку — ответственность приложения и фоновых процессов.
- JSONB можно использовать, когда документ живёт рядом с PG транзакцией; Mongo лучше для самостоятельного контентного домена с изменчивой структурой. В обоих сценариях проверяются одинаковые документы, **не заявляется фиктивное ускорение**.
