# Индексы и методика измерений

## Два запроса на полях Lab5

**Q1:** последние одобренные отзывы страницы `lab6-seed-page-000007`, фильтр `{pageSlug, moderation:'approved'}`, сортировка `{createdAt:-1,_id:1}`, limit 100. Индекс Lab5 `{pageSlug:1,moderation:1}` отбирает кандидатов, но не удовлетворяет сортировке. Добавлен `lab6_feedback_page_moderation_created_id` с ключом `{pageSlug:1,moderation:1,createdAt:-1,_id:1}`.

**Q2:** опубликованные страницы редактора `editor-07`, фильтр `{status:'published','editor.alias':'editor-07'}`, сортировка `{headline:1,_id:1}`, limit 100. Индекс Lab5 `{status:1,keywords:1}` не покрывает редактора и сортировку; оптимизатор может предпочесть COLLSCAN. Добавлен `lab6_pages_status_editor_headline_id`: `{status:1,'editor.alias':1,headline:1,_id:1}`. Поле `editor.alias` действительно существует в исходном валидаторе и seed Lab5.

Оба новых индекса используют равенства перед полями сортировки. Возвращается полный документ, поэтому ожидается FETCH. `_id` разрешает совпадения значений сортировки. Предварительное измерение сохраняет **все бизнес-индексы Lab5**: нельзя заранее объявлять его COLLSCAN, если оптимизатор выбрал IXSCAN. Код извлекает стадии только из winning/executed plan, исключая rejected plans.

## Как воспроизвести

```bash
bash scripts/lab6.sh seed
bash scripts/lab6.sh benchmark
bash scripts/lab6.sh index-write
bash scripts/lab6.sh check
```

`benchmark` требует seed и выполняет по 3 прогревочных обычных запроса и минимум 5 `explain('executionStats')` на каждую фазу каждого запроса. Между фазами меняется только принадлежащий Sprint 6 индекс. Нет `hint`, очищения кеша ОС или искусственной задержки. Проверяется равенство упорядоченных ID и сохранение бизнес-индексов. Результаты фиксируют число возвратов и все четыре запрошенные метрики; отдельно измеряется время round trip `performance.now()`.

Медиана сортирует копию значений; для чётного числа берётся среднее двух центральных. Изменение скорости не является обязательным условием успеха: время сервера имеет миллисекундную дискретность и может быть нулевым. Обязательные условия — реальное использование нового индекса, отсутствие блокирующего SORT и уменьшение `totalDocsExamined` на данном селективном наборе. Если они не выполнены, команда завершается ошибкой и оставляет полный план для диагностики; нельзя подменять выбор оптимизатора принудительным hint.

## Цена индекса для записи и хранения

`index-write.mjs` применяет один и тот же массив из 6000 детерминированных отзывов к двум выделенным коллекциям с одинаковым валидатором. Обе имеют `_id` и исходный `{pageSlug,moderation}`; только indexed имеет дополнительный Q1-индекс. Выполняются прогрев и пять повторов каждой фазы с чередованием порядка. Во всех случаях запись подтверждается majority + journal.

В каждом повторе: пустой scoped-набор → `insertMany` → `collStats` → `updateMany(createdAt)` → `collStats` → очистка. Изменяется индексируемое поле, поэтому измеряется также обслуживание индекса при UPDATE. Скорость = число документов / wall time в секундах; сводка содержит медианы времени и пропускной способности отдельно. SHA256 и logical data bytes подтверждают одинаковый набор; результаты benchmark чтения для этого эксперимента не используются.

- [Сырые CSV записи](../../artifacts/lab6/index-write/measurements.csv), [медианы](../../artifacts/lab6/index-write/medians.csv).
- [Сводка](../../artifacts/lab6/index-write/summary.md), `stats-{before,after}-{1..5}.json` содержат полные collStats вставки и обновления.

`collStats` поддерживается MongoDB 7.0. `size` — логический размер, `storageSize` — выделенное сжатое хранилище WiredTiger, `totalIndexSize` — выделенные байты индексов. Статистика зависит от checkpoint/кеша; освобождение документов не обязано уменьшать выделенные файлы. Коллекции не пересоздаются, high-water allocation сохраняется. Индекс обычно требует дополнительных CPU/IO/места, но конкретное соотношение времени может колебаться, поэтому замедление не утверждается заранее.

Технические источники: [MongoDB executionStats](https://www.mongodb.com/docs/v7.0/reference/explain-results/), [collStats](https://www.mongodb.com/docs/v7.0/reference/command/collStats/).
