# 3НФ и намеренная денормализация

## Нормализованный вариант суммы заказа

В полностью нормализованной модели сумма заказа вычисляется из `order_items`:

```sql
SELECT SUM(unit_price) AS subtotal
FROM app.order_items
WHERE order_id = :order_id;
```

Комиссия также могла бы вычисляться по текущему тарифу платформы.

## Использованный вариант

В `app.orders` хранятся:

- `subtotal_amount`;
- `platform_fee_amount`;
- `total_amount`.

Это осознанная денормализация/снимок финансового результата заказа.

### Обоснование

1. BR-9 требует, чтобы комиссия фиксировалась в момент создания заказа и не менялась при возврате.
2. Исторический заказ должен сохранять фактически зафиксированные суммы, даже если тариф платформы изменится.
3. Получение списка заказов не требует каждый раз агрегировать все `order_items`.
4. Ограничение `total_amount = subtotal_amount + platform_fee_amount` защищает внутреннюю непротиворечивость снимка.

Таким образом, нормализованная модель лучше отражает структуру данных, а выбранная денормализация сохраняет бизнес-факт, который должен быть неизменным после создания заказа.
