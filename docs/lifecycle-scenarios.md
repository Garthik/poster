# Сценарии жизненного цикла

## Event

`draft -> published`

Переход выполняется `app.publish_event(event_id)` и требует хотя бы одну категорию билетов с положительной квотой.

## Order

`pending_payment -> paid`

Переход выполняется `app.pay_order(order_id)`.

## Ticket

`reserved -> valid -> scanned`

Бронь создаётся через `app.reserve_zone_ticket(...)`, выпуск выполняется вместе с оплатой заказа через `app.pay_order(...)`, вход фиксируется `app.scan_ticket(...)`.

## Отдельно проверяемые исключения

- нельзя опубликовать мероприятие без квоты;
- нельзя оплатить заказ, не ожидающий оплаты;
- нельзя использовать билет вне интервала `±12 часов` от начала мероприятия;
- нельзя повторно просканировать билет после перехода в `scanned`;
- нельзя вернуть билет ближе чем за 72 часа до начала мероприятия.
