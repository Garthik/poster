# Логическая модель PostgreSQL

## Сущности и кардинальности

- `users 1:N events` — один организатор создаёт много мероприятий.
- `venues 1:N events` — на одной площадке проводится много мероприятий во времени.
- `venues 1:N venue_seats` — площадка содержит физические места.
- `events 1:N ticket_categories` — мероприятие имеет категории билетов.
- `events M:N venue_seats` через `event_seats` — конкретные места могут быть включены в конкретное мероприятие.
- `users 1:N orders` — пользователь создаёт заказы.
- `events 1:N orders` — у мероприятия много заказов.
- `orders 1:N order_items` — заказ содержит несколько билетов/позиций.
- `order_items 1:1 tickets` — после резервирования позиция получает билет.
- `orders 1:N payments` — один заказ может иметь несколько платёжных попыток/callbacks.
- `tickets 1:0..1 refunds` — конкретный билет может быть возвращён один раз.
- `tickets 1:N ticket_scans` — попытки проверки можно хранить для аудита.
- `users 1:N ticket_scans` — контролёр выполняет проверки.

## Почему схема находится в 3НФ

Факты, принадлежащие разным сущностям, не дублируются: данные пользователя находятся в `users`, мероприятия - в `events`, категории - в `ticket_categories`, физические места - в `venue_seats`, а операция покупки - в `orders/order_items`.

Производные значения, которые нужны для финансового снимка заказа, вынесены в `orders` как осознанное решение о денормализации (см. `docs/normalization.md`).
